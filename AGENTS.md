# AGENTS.md

2D 1v1 browser fighting game ("After Hours"). Stack: TypeScript, Phaser 3, Vite. Tests: Vitest.

## Hard rules

1. **Simulation is fully separate from rendering.** Everything in `src/sim/` must not import
   Phaser, the DOM, or anything from `src/render/`, `src/input/` or `src/ai/`. The renderer reads
   sim state; it never writes it.
2. **The sim is a pure function:** `step(state, p1Input, p2Input) -> state`. It never mutates its
   argument and has no hidden state. Hero data (`HEROES`) is immutable constant data.
3. **Fixed 60 ticks per second.** The renderer runs an accumulator and calls `step` once per
   1/60 s. Nothing in the sim knows about wall-clock time.
4. **Integer math only in the sim.** No floats, no `/` division (use shifts), no decimal
   literals. No `Math.random`, no `Date`, no `performance`. Only `Math.abs`, `Math.min`,
   `Math.max`, `Math.imul` are allowed. `tests/sim.test.ts` scans `src/sim/` to enforce this.
5. **Inputs are a bitmask per tick:** left=1, right=2, up=4, down=8, light=16, heavy=32,
   special=64, block=128 (see `src/sim/input.ts`). Everything else is read from these bits:
   kick is forward + heavy, sweep is down + heavy, throw is light + heavy, super is heavy + special,
   specials use motions read from the per-fighter input history (`hist`).
6. **Fighters are data driven.** Each hero is one JSON file in `src/heroes/`: stats plus per-move
   frame data (startup, active, recovery, damage, hitstun, blockstun, knockback, guard, cancels,
   hitstop, projectiles, and hitbox and hurtbox rects for every frame). No hero-specific logic in
   the sim.

## Layout

- `src/sim/` deterministic simulation (`step.ts`, `types.ts`, `constants.ts`, `hash.ts`, `heroes.ts`, `input.ts`)
- `src/heroes/*.json` hero data, generated by `scripts/gen-heroes.mjs` from compact specs. Edit the
  specs there and run `npm run gen:heroes` (rerunning overwrites hand edits to the JSON).
- `src/render/` Phaser front end:
  - `scenes/` Boot (loading), Title (main menu and options), Select (fighters and stage), Versus
    (splash), Fight, Result, HowTo (controls, basics, move lists)
  - `heroArt.ts` maps sim state to atlas frames; `heroInfo.ts` titles, quotes and ratings;
    `stages.ts` stage art and ambience; `hud.ts`; `fx.ts` procedural effects; `audio.ts` music and
    sound; `ui.ts` menu widgets; `moves.ts` move list text; `trials.ts` combo trials and the combo tracker
    (training mode, F4); `superFx.ts` super cinematics; `config.ts` sizes, colours, game title
- `src/input/controls.ts` keyboard (two players on one keyboard) and gamepads, plus menu events
- `src/ai/cpu.ts` computer opponent (easy, normal, hard) and the training dummy's auto-guard
- `assets/heroes/<id>/` sprite frames, `atlas.png` and `atlas.json` (repack with
  `python3 scripts/pack-hero-atlas.py <id>`). Frames are feet-aligned on a 200 px cell, anchor
  (100, 170), and drawn at 2x, so heroes are about 240 px tall.
- `assets/stages/` stage art (768x320, drawn at 2x); `assets/audio/` sound effects and music loops
- `tests/sim.test.ts` determinism, match flow, guarding, specials, combos (every trial route for every
  pair of fighters), movement, training and data tests

## Sim conventions

- Units are whole pixels and pixels per tick. `x` is the fighter's feet centre, `y` is height
  above the floor (up is positive). Stage is `0..STAGE_WIDTH` (wider than the 960 px screen; the
  camera follows) with walls at both ends; fighters stay within `MAX_SEPARATION` of each other.
- Rects in hero JSON are fighter-local: `x` = forward offset of the near edge (mirrored by
  facing), `y` = bottom edge above the feet, `w`, `h`.
- Every hero has the moves in `MOVE_KEYS`: light, heavy, kick, crouchLight, sweep, jumpAttack,
  throw, special, projectile, rising, super.
- `frames.length` of a move must equal `startup + active + recovery`; hitboxes only on active
  frames (projectile moves have none: the projectile hits).
- Any new field on the state must be added to `hashState` (`FIGHTER_KEYS` / `GAME_KEYS`); a test
  fails if one is missed. `cloneState` copies with spread, so only arrays need special care.

## Commands

- `npm run dev` play locally
- `npm test` run the tests (must pass before finishing any change)
- `npm run build` typecheck and bundle
- Pushing to `main` or `main-q5hjl6` runs `.github/workflows/deploy.yml`, which tests, builds
  and publishes `dist/` to the `gh-pages` branch (GitHub Pages).

## Done criteria for sim changes

The determinism test must pass. If you change sim behaviour or hero data on purpose, the golden
hash in `tests/sim.test.ts` changes: update it with `npx vitest run -u` and say so.
